## Architecture and contract

Optional numeric snapshot and report: trialDiagnostics (fv-optical-measurement-1 / fv-trial-diagnostics-1). Persistence: trialStore, original key fv.livingTrial.v1 with optional versioned diagnostics fields. UI: LocalOptics / LivingTrial. No skin algorithm.
Model: MediaPipe Tasks Vision 0.10.35; float16/1 face landmarker, manifest SHA-256 64184e229b263107bc2b804c6625db1341ff2bb731874b0bcc2fe6544e0bc9ff. Pinned source and runtime hashes in local-optics-assets.json. The protected lab build at ee34b97 verified pinned assets and reached READY; the owner subsequently exercised it on an iPhone.
Measurements: apparent eye-corner scale is normalized to analyzed frame width, not physical distance; x/y are fractions of analyzed frame, origin top-left; roll is image eye-line degrees; yaw/pitch are model estimates in degrees with unverified device sign; brightness is camera-processed sRGB luma (0–255), not lux; side shading is a dimensionless image-side asymmetry proxy, not direction or calibrated illuminance. Relative difference for scale and brightness is (follow-up minus baseline)/baseline, other checked properties use absolute-unit signed differences. Motion is RMS interocular units per analyzed frame; clipping is fraction of face pixels. Frame dimensions are analyzed pixels, not necessarily sensor size. Missing/nonfinite values are null. The rounded baseline is not a raw capture. Numeric uncertainty is unknown, not zero.
Existing exploratory gates and tolerances unchanged: roll 5°, yaw/pitch 8°, scale 10%, center 0.06, luma 15%, shading 0.10; motion 0.02 interocular/frame, clipped fraction 0.02, minimum frames 5. Frame change is noncomparable. A matched comparison only means these experimental checks matched; no downstream skin score is authorized. See local-optical-comparability.md for existing guide and thresholds.
Version changes affecting values, units, gates or semantics require explicit versioning and compatibility review; never silently compare across changed contracts.

Existing records lack optional fields; do not infer missing values, reset or rewrite merely to export. Numeric diagnostics are allowlisted on read/export, excluding images, raw landmarks, user agent, product and free-text goals. Relative minute timing; locally generated session ID where recognizable; ordinal capture IDs. Browser storage is not encrypted, synced or durable. User deletion removes the same record. No automatic telemetry. Failed/cancelled scans outside an accepted capture and detailed device capabilities remain unavailable. Old FV05 code can discard optional fields if it rewrites a trial; export before rolling back. No destructive migration.
## Acceptance protocol (capture, export and restart demonstrated)
Open the exact same Safari origin as the November 23 trial. Review and export historical evidence first. Do not delete it. Enable optional numeric diagnostics. If the baseline conditions can be reproduced, restore it; otherwise preserve that trial and use a separate test origin or browser profile for a new controlled baseline. Mark phone and chair locations, use fixed diffuse light, same front camera orientation, same background, no beauty filters or changes in cosmetics; allow exposure to settle.
1. Capture five repeats without changing phone/face/light; record automatic vs manual, time and all outcomes. Engineering target: 5 accepted captures, each matched or documented with specific reason; any mismatch investigated, no thresholds changed. Report distributions, median/range, within-session deviations and missingness.
2. Lighting only: change lamp output/position without moving phone/head. Capture manually if guide holds; expect light mismatch or hold/rejection when deviation is substantial. Auto exposure may compensate; no mismatch is a finding, not a reason to force a result.
3. Restore light and position. Distance only: move phone straight along optical axis using marked locations, keep center/orientation. Expect scale guidance or mismatch; a severe change may be rejected.
4. Restore all; angle only: rotate head slightly in yaw with phone fixed and center maintained; record intended variable and any coupled scale/position. Expect angle response for substantial deviations. Repeat independently for pitch and roll in extended tests.
5. Close and reopen Safari; verify baseline and count survive (not Private Browsing). Export JSON, check old rows remain categorical and newly opted-in rows contain actual numeric deviations. ## FV07 research handoff (separate research branch; not part of FV06)
See [FV07 research protocol](fv07-visible-redness-research.md). The physical data supports preserving current tolerances, not treating them as scientifically validated color eligibility. No skin-measurement feature is added.
Use stable frame, pose, scale, luma and shading eligibility as preconditions, not redness measurements. Research linearization/color management, neutral reference and exposure/white balance control, specular masking and anatomically consistent cheek/forehead ROIs excluding lips, eyes, hair, cosmetics and shadows. Evaluate visible color across skin tones, camera models and illumination, with calibrated color targets and appropriate colorimeter/spectrophotometer reference where feasible; consented diverse datasets and stratified repeatability/error. Establish within-person repeatability, limits of agreement, uncertainty and abstention for missing reference, unsuitable lighting, occlusion, drift, motion or out-of-distribution conditions. Visible redness is not inflammation, disease, treatment response or diagnosis.
